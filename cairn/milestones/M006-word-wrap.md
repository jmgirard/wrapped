# M006: Wrap figures in Word output with frames

- **Status:** review
- **Priority:** high
- **Depends on:** —
- **Driving RR:** —
- **Principles touched:** —
- **Resolves:** —
- **Surface tier:** user-facing — it changes the docx that users get from a wrapped figure
- **Branch/PR:** m006-word-wrap

## Goal

A document rendered to Word with the extension installed shows body text beside each figure marked `.wrap-left` or `.wrap-right`, in Word.

## Scope

**In:**
- A `post-render` filter entry in `_extension.yml`. In docx it removes Quarto's one-cell figure table for each wrapped float, captioned image with no id, and uncaptioned image, and gives the image paragraph and each caption paragraph the same `w:framePr` (W4, spike S4). Word leaves the format fallback.
- The group of paragraphs beside each frame follows the HTML grouping and the stop rule. The image width equals the frame width.
- Width and gap conversions to twips, with the text width read from the reference doc's `w:sectPr` through `pandoc.zip`. The `wrapped:` metadata, and the context, next-block, and unplaced warnings, for docx.
- Checks in Word, driven through AppleScript, and in LibreOffice, installed with Homebrew (D-005). The user looks in Google Docs at review.
- docx renders of the fixture, defaults, stop-rule, contexts, and a reference-doc fixture in `tests/verify.py`, and a Word section in `README.md`.

**Out:**
- `wrap-lines`, which stays LaTeX only (DESIGN syntax table).
- A cell with two figures → the candidate "Handle a wrapped cell with two figures".
- EPUB → the candidate "Use the HTML stylesheet for EPUB".
- Running the fixture renders in CI → the candidate "Run the fixture renders in CI".
- Quarto versions other than 1.10.19, Word versions other than the one on this Mac, and renders of a project.

## Acceptance criteria

- [x] AC1: `quarto render tests/fixture.qmd --to docx` exits with status 0 and prints no "docx output does not wrap figures yet" warning. In its `word/document.xml`, each figure and image that is in a `.wrap-group` in the fixture's HTML render, matched in document order, sits in no `w:tbl`. Its image paragraph and each of its caption paragraphs carry, in one of their `w:pPr` elements, a `w:framePr` with `w:wrap="around"`, `w:hAnchor="margin"`, and a `w:xAlign` that names the figure's side. Within each figure, those `w:framePr` elements carry the same `w:w` and `w:hSpace`, and the image's `wp:extent` `cx` equals that `w:w` at 635 EMU per twip, within 635 EMU. Each caption paragraph carries `w:pStyle w:val="ImageCaption"`, each figure with a `#fig-` id has a bookmark of that name around its frame, and each image with `fig-alt` carries that text in its `wp:docPr` `descr`.
- [x] AC2: In the same file, the paragraphs of each such `.wrap-group` follow its frame in source order, and no other block sits between the frame and them. A parse of the file finds no `w:framePr` with `w:wrap="around"` on any paragraph outside those frames.
- [x] AC3: Microsoft Word on this Mac opens the fixture's docx with no repair or error dialog. On page images of Word's PDF export of it, made with `pdftoppm`, each frame from AC1 sits whole on one page on its figure's side, with its caption inside the frame's width. Lines of the first paragraph of its group sit beside it on the same page, no text line overlaps it, and the block after its group starts below its bottom edge. This holds for a frame of the fixture that starts within its own height of a page's bottom edge. The PDF text from `pdftotext` holds every paragraph of each group.
- [x] AC4: On AC3's page images, the image of `#fig-md` (`width="30%"`) measures 28% to 32% of the text-block width. In `word/document.xml` of the fixture and of `tests/defaults.qmd`, each `width` and `wrap-gap` of a figure or image in AC1's domain becomes the twips this rule gives. A percent above 0% and below 100% is that share of the text width: the page width less the left and right margins in the `w:sectPr` of the reference doc that the render uses, or, where that `w:sectPr` has no `w:pgSz` or `w:pgMar`, the text width that Word's page images of the fixture show, which the README states. Any other percent takes the default, with a warning. An `in`, `cm`, `mm`, `pt`, or `pc` length in any letter case converts at 1440 twips per inch. A `px` length, or a number with no unit, converts at 15 twips per px. An `em` length converts at 240 twips per em. Any other value, `rem` and `ex` among them, takes the default, with a warning. A gap converts by the same rule and becomes `w:hSpace`. `tests/defaults.qmd` renders to docx with exit status 0, and a figure there that sets neither attribute takes the `wrapped: width` and `wrapped: gap` metadata. `tests/docx-reference.qmd`, whose reference doc `tests/reference-narrow.docx` sets a page width and left and right margins that each differ from Letter with 1 in margins, renders to docx with exit status 0, and its percent widths follow that reference doc's text width.
- [x] AC5: `tests/stop-rule.qmd`, `tests/contexts.qmd`, and `tests/defaults.qmd` each render to docx with exit status 0. For each, AC1's frame check and AC2's first sentence hold against each `.wrap-group` in the HTML render of that fixture, matched in document order. No figure or image that keeps a normal layout in HTML is in a paragraph whose `w:framePr` has `w:wrap="around"`. Each render prints each extension warning of the HTML render of that fixture the same number of times, plus one warning for each value that AC4's rule sends to the default and one for each `height` attribute that the fixture's source sets on an image of a figure or image in a `.wrap-group` of that HTML render, and no other extension warning.
- [x] AC6: The README's Word section states, for Word, LibreOffice, and Google Docs, whether text sits beside the fixture's wrapped figures, and names each figure that an app shows otherwise. Each statement matches that app's view of the fixture's docx: for Word and LibreOffice, the page images of its PDF export (LibreOffice through `soffice --headless --convert-to pdf`); for Google Docs, the user's look at review.
