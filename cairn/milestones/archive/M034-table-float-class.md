# M034: Warn for wrap classes on table floats

**Status:** done (2026-10-29, PR #36 https://github.com/jmgirard/wrapped/pull/36)

**Goal:** A `#tbl-` float whose wrap class is in the attribute block at its caption's end prints the table warning and keeps its normal layout in HTML.

**Outcome:** In `wrapped.lua`, `caption_block` reads the block at a caption's end as Quarto's `parseTableCaption` does and now serves `unplaced_table` too. `drop_caption_wrap` runs in `float_target` on every table float: it takes the block's wrap class for the "the table #<id> is not a figure, so it does not wrap." warning (after the float's own, a carried, and an image class), drops the Space before the block, and writes the block again from its parsed attributes without wrap classes (an id kept only when the text opened with `{#`), or drops it when nothing is left. So Quarto's `table_classes()` adds no wrap class to the float or its table, and `.striped` and other classes still apply. Forms tested: a `#tbl-` div around `: Cap {.wrap-left .striped}`, a knitr `tbl-cap` block, a cell with both `classes:` and a block, and a `{.striped}`-only block. `tests/verify.py` gains `TABLE_IDS`, `table_summary` (HTML: wrap classes on each table, `table-striped` where the block sets it, caption text) and `tex_table_summary` (LaTeX caption and whether it ends in white space). `docs/normal-layout.qmd` Tables section and DESIGN.md step 6 state the rule.

**Decisions:** none milestone-local. The plan gate removed the class rather than warn only, at the user's choice, since `wrapped.css` selects `.quarto-float.wrap-*` (M033's falsifying condition), and chose rewriting the block over narrowing the CSS selectors, which cannot tell a table float from a figure float (falsified by a Quarto version that applies the block before pre-quarto filters).
