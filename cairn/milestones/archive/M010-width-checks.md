# M010: Check figure widths before use

**Status:** done (2026-10-27, PR #10 https://github.com/jmgirard/wrapped/pull/10)

**Goal:** A wrapped figure whose width is zero, is CSS that the filter cannot check, or is as wide as the Typst text or wider takes the default width.

**Outcome:** `checked_length` warns on a width that is zero written as a number (`0%`, `0in`, `0IN`, `0`, `0.0px`, `.0`) and takes the fallback in HTML, PDF through LaTeX, and PDF through Typst, with the same wording as Word; a zero gap stays. A recursive parser above `css_length` (`calc_sum`, `calc_product`, `calc_value`, `calc_args`, `calc_length`) reads `calc()`, `min()`, `max()`, `clamp()`, and `var()` by the CSS Values 3 calc() rules and Values 4 section 10.2, with every Values 4 length unit in `UNITS`; a value that fails prints the existing "is not a length or a percent" warning. A breakpoint refuses percents and `var()`. `meta_text` restores `--` from Pandoc's en dash in metadata. Each Typst call is now `#layout(wrapped-size => wrap-content(...))` closed by `]))`, and `wrapped-width(size, ..widths)` in `TYPST_HEADER` returns the first of the figure width, the document default, and 40% that is a percent or narrower than the text, with no console warning. Tests: fixtures zero-meta, zero-width, css-functions, meta-calc-bad, meta-calc-good, meta-calc-var, typst-wide, typst-wide-meta; a `TYPST_LAYOUT` table in `tests/verify.py` reads the Typst PDF with pdftohtml (40% is 259 px, 2in is 216 px). 51 renders on macOS and in CI. README, DESIGN, PROFILE, wrap-mechanisms, and a new CSS Values source note updated.

**Decisions:** none milestone-local. Plan choices in the work log: a Typst-side guard with no warning over a filter-side estimate of the text width; the CSS Values 3 rules plus the four functions over a full Values 4 parser. Both limits went to DESIGN Known issues.
