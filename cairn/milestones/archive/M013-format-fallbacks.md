# M013: Fall back where a format cannot wrap

**Status:** done (2026-10-27, PR #13 https://github.com/jmgirard/wrapped/pull/13)

**Goal:** If a format cannot wrap a figure where it sits, the figure keeps its normal layout with one warning. No CSS number overflows in the filter's conversions.

**Outcome:** `find_contexts` treats a definition list as a list and a `fig-column-margin` cell as a margin context in every format. `block_context` adds format-dependent contexts: a block quote in LaTeX, and a table in LaTeX and Word. `page_context` reads Quarto's 16 page-wide classes (`PAGE_WIDE`, a `fig-` prefix stripped for cells) on HTML pages, and in LaTeX for the `isStarEnv` names, on floats and divs only. `caption_location` reads a figure's `fig-cap-location`, then its `cap-location`, then the metadata's, and an HTML page falls back on `margin`, in `float_target` and in `figure_block`. `has_page_layout` (HTML, not revealjs) keeps slides wrapping. CSS numbers read as floats before `*` or `+` in `docx_measure`, `typst_length`, `typst_fills`, and `tex_length`. `tests/verify.py`'s Typst summary reads indented calls and figures in table cells. New fixtures: table-cell, table-cell-image, cap-margin (three files), page-wide, docx-overflow, typst-overflow, with cases added to contexts and revealjs (76 renders). README "Where a figure keeps its normal layout" and Slides name each case.

**Decisions:** none milestone-local. The question set chose falling back only in the formats that fail over all four formats, and fixing the overflow in Word and Typst. One scope amendment dropped a wrong Out item (a cell's `cap-location-margin` classes reach the figure as its `cap-location`).
