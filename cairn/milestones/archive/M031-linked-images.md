# M031: Wrap images inside links in all formats

**Status:** done (2026-10-29, PR #33 https://github.com/jmgirard/wrapped/pull/33)

**Goal:** In HTML, PDF through LaTeX, PDF through Typst, and Word, a wrapped image that is the only content of a link, which is the only content of its paragraph, wraps with its link and alt text as an unlinked image does, and in Word a framed captioned figure with a linked image keeps its paragraph style.

**Outcome:** In `wrapped.lua`, `lone_wrapped_image` uses a new `only_inline` helper to accept a Para whose one inline, spaces aside, is a Link whose one inline is a wrapped Image, and returns the image and the link; `placed_image` puts the link, holding the cleaned image, in each format's box (`wrapped_image_div`, `_typst`, `_docx`, `_tex`). The next-block rule now treats such a paragraph as a wrapped image, so a wrapped figure right before it keeps a normal figure (D-003). A captioned linked image was already a Figure or float in Quarto 1.10.19. In `wrapped-docx.lua`, `has_image` also finds an image inside a link, so a linked captioned figure's image paragraph keeps `Compact` or `CaptionedFigure`. Tests: the fixture's linked case now wraps, five new cases each with its own image copy (`tests/link*.png`), two linked figures in `tests/docx-alt.qmd`, and `link=` fields in all four summaries plus a `style=` field for `docx-alt` frames in `tests/verify.py`. `docs/get-started.qmd`, `docs/normal-layout.qmd`, and DESIGN.md (Syntax and next-block rule) state the rule.

**Decisions:** none milestone-local. No D-entry: D-003 applies as written.
