# M033: Warn for a wrap class on a span

**Status:** done (2026-10-29, PR #35 https://github.com/jmgirard/wrapped/pull/35)

**Goal:** In HTML, PDF through LaTeX, PDF through Typst, and Word, a span, heading, inline code, code block, or captioned table with no `#tbl-` id that carries a wrap class prints a warning, since the class wraps nothing there.

**Outcome:** In `wrapped.lua`, `unplaced_span`, `unplaced_header`, `unplaced_code`, `unplaced_code_block`, and `unplaced_table` join the last pass beside `unplaced_link`. They share `warn_unplaced`, which sets `found_wrap` and, where `wraps()` holds, warns "the <kind> <where> is not a figure, so it does not wrap. A wrap class goes on an image or a figure." `warning_name` gives `#<id>`, else the trimmed first line in quotes cut after 40 code points with `...`, else "with no text". `unplaced_table` reads the caption's last block for a trailing `{…}` attribute block as Quarto's `parseTableCaption` does (one trailing Space removed), since Quarto's `table_classes()` applies it after pre-quarto filters, and names the table by the caption text before it. Each element keeps its class. Tests: cases (a) to (h) in `tests/fixture.qmd` in all four snapshots, span cases in `tests/twocolumn.qmd` and `tests/docx-columns.qmd`, and a new `tests/docx-columns-span.qmd` (span only, one Word columns warning). `docs/normal-layout.qmd` and DESIGN.md step 6 state the rule.

**Decisions:** none milestone-local. The plan gate kept the class on each element at the user's choice (falsified by a stylesheet that selects a wrap class on these elements) and read the caption block with Quarto's own rule (falsified by a Quarto version whose parser differs). Raw HTML such as `<table class="wrap-left">` stays out, as a RawBlock with no attributes at the filter's stage.
