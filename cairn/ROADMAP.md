Widths at or above the text width take the default since M006 (M006 review, diff-bug #4). The docx-gap fixture's `fig-below` (8640-twip frame, 8400-twip image) records the case (M012 review, diff-bug #1) — added 2026-10-26 — milestones/archive/M006-word-wrap.md

- Trim the LaTeX stop gap at page tops: a wrapped figure placed at the top of a page leaves about one more blank line before its stop block than one in mid-page (60 px against 39 px in a scratch render), since wrapfig counts its lines from a height less \intextsep there. No fixture covers a page-top figure, a wrap-lines smaller than the height needs, or a group that ends at a div's end (M007 review, diff-bug #7). The skip counts lines and ignores \parskip, so the gap below a figure grows about 10 px for each paragraph beside it, and when narrowed lines cross a page break the stop skips about 2 empty lines at the next page's top with no figure there (M007 review pass 2, diff-bug #3 and #4) — added 2026-10-26 — milestones/M007-latex-stops.md
- Stop text overlap with small wrap-lines: in LaTeX a `wrap-lines` value smaller than the figure's height ends the wrap after that many lines, so later text and a stop block can sit over or beside the figure (wrapfig did this before M007); with one short paragraph the stop moves the block to the figure's full bottom instead. The README's "wrapping stops as in HTML" does not hold for such a value (M007 review pass 2, diff-bug #1 and #5) — added 2026-10-26 — milestones/M007-latex-stops.md
- Fix the overfull LaTeX fixture page: in tests/fixture.qmd's PDF through LaTeX, page 4 runs past the page bottom (Figure 7 off the page) when a floating figure lands on the page with the knitr longtable. M007's stop spacing moved the fixture's content so that this happens; `main` renders it within bounds but overflows the same way with an 8-line hand shift, so the clash between the float and the longtable predates M007 (M007 review, prior-review #2 in both passes) — added 2026-10-26 — milestones/M007-latex-stops.md
- Keep wrapped figures in multicols: with `classoption: twocolumn` the filter writes Quarto's normal float for a wrapped figure, and LaTeX drops it inside a raw `multicols` (multicol's "Floats and marginpars not allowed" warning; by-hand render at M009 implement). - Fall back in more margin and page forms: Quarto also puts a caption in the margin for the `.margin-caption` and `.caption-margin` classes, and a document-level `fig-column` makes figures page-wide (corrected M013: a cell's `cap-location-margin` classes reach the figure as its `cap-location`, so M013 covers them). M013 checks only the `cap-location` and `fig-cap-location` keys and page-wide classes on a div, a figure, or a cell, so these forms wrap with no check (M013 criteria audit) — added 2026-10-27 — milestones/M013-format-fallbacks.md — started M015
- Read cap-location before fig-cap-location: Quarto 1.10.19 puts a figure's caption in the margin by `cap-location` when it also sets `fig-cap-location`, but `caption_location` and the README read `fig-cap-location` first, so in HTML `fig-figcap-first` in `tests/cap-margin.qmd` wraps while its caption sits in the margin. A user-visible bug since M013; door: `/hotfix` (M015 claim audit) — added 2026-10-27 — milestones/M015-margin-page-forms.md
- Read fig-column over a figure's class: the filter reads a figure's own column class, or a cell's own `fig-column` or `column` option, before the document's `fig-column` or `column`. Where they name different places, it can keep a figure normal with the wrong reason, or in a format where Quarto puts it in the body, such as a `.column-margin` figure in a `fig-column: body` document. No fixture sets both document keys, and none sets `column: margin`; the README names `column` only for page-wide columns (M015 criteria audits) — added 2026-10-27 — milestones/M015-margin-page-forms.md
