- Handle a wrapped cell with two figures: a code cell with `#| classes: wrap-right` that makes two figures floats both side by side in HTML. Decide whether such a cell wraps its first figure, falls back with a warning, or joins the subfigure fallback (E4). Found at M002 review (diff-bug #5, blame-history #3). A cell with `fig-subcap` or `layout-ncol` now keeps a normal panel with a warning (M003). In Typst both figures go in one box with the first figure's side and width (M005 review, blame-history #3) — added 2026-10-24, narrowed 2026-10-25 by M003 review — milestones/M002-html-wrap.md
- Check wrapped figures in dashboards: in a Quarto dashboard the `.wrap-group` div likely gets `html-fill-container`, a flex container, where a float has no effect. Not verified. Make wrapping work there or fall back with a warning. Found at M002 review (diff-bug #9) — added 2026-10-24 — milestones/M002-html-wrap.md
- Fall back in other margin and list forms: a cell with `#| fig-column: margin` floats inside the margin with no warning, and a figure in a loose definition list wraps. `cap-location: margin` and `.column-page` are untested. M003 left these out of scope (M003 review, diff-bug #4 and #6). In Typst a figure in a definition list or a table cell wraps too, and a call in a table cell is indented, so the `.typ` summary does not read it (M005 review pass 2, diff-bug #4). A wrapped figure in a block quote never wraps in LaTeX and prints no warning (M007 review pass 2, diff-bug #6) — added 2026-10-25 — milestones/archive/M003-context-fallbacks.md
- Bound wide absolute widths in Typst: a wrapped figure whose absolute width, such as `7in`, is as wide as the text column or wider leaves no room for the text in wrap-it's grid, and the text can drop from the PDF with no warning. The filter cannot know the text width, so a check would run in Typst. Percents of 100% or more are handled in M005 (M005 review, diff-bug #2) — added 2026-10-25 — milestones/M005-typst-wrap.md — started M010
- Warn when a figure width is zero: `width="0%"` passes the length checks, and in Typst it gives an empty box and a caption broken into a zero-width column with no warning; HTML takes the same value (M005 review pass 2, diff-bug #5) — added 2026-10-25 — milestones/M005-typst-wrap.md — started M010

Make wrapping work there or keep a normal figure with a warning, as LaTeX does for two columns. Left out of M005 — added 2026-10-25 — milestones/M005-typst-wrap.md
- Check CSS function lengths before use: `css_length` passes any `calc()`, `min()`, `max()`, or `clamp()` text unread, so `width="calc(banana)"` or `breakpoint: calc(50%)` reaches the CSS with no warning (M003 review, prior-review #1; same class as M002 review pass 1 finding 7) — added 2026-10-25 — milestones/archive/M003-context-fallbacks.md — started M010

- Trim the LaTeX stop gap at page tops: a wrapped figure placed at the top of a page leaves about one more blank line before its stop block than one in mid-page (60 px against 39 px in a scratch render), since wrapfig counts its lines from a height less \intextsep there. No fixture covers a page-top figure, a wrap-lines smaller than the height needs, or a group that ends at a div's end (M007 review, diff-bug #7). The skip counts lines and ignores \parskip, so the gap below a figure grows about 10 px for each paragraph beside it, and when narrowed lines cross a page break the stop skips about 2 empty lines at the next page's top with no figure there (M007 review pass 2, diff-bug #3 and #4) — added 2026-10-26 — milestones/M007-latex-stops.md
- Stop text overlap with small wrap-lines: in LaTeX a `wrap-lines` value smaller than the figure's height ends the wrap after that many lines, so later text and a stop block can sit over or beside the figure (wrapfig did this before M007); with one short paragraph the stop moves the block to the figure's full bottom instead. The README's "wrapping stops as in HTML" does not hold for such a value (M007 review pass 2, diff-bug #1 and #5) — added 2026-10-26 — milestones/M007-latex-stops.md
- Fix the overfull LaTeX fixture page: in tests/fixture.qmd's PDF through LaTeX, page 4 runs past the page bottom (Figure 7 off the page) when a floating figure lands on the page with the knitr longtable. M007's stop spacing moved the fixture's content so that this happens; `main` renders it within bounds but overflows the same way with an 8-line hand shift, so the clash between the float and the longtable predates M007 (M007 review, prior-review #2 in both passes) — added 2026-10-26 — milestones/M007-latex-stops.md
